# Synthetic datasets — AI-Powered Public Supply Chain Intelligence Platform

These scripts generate **synthetic demonstration data** aligned with the project proposal's focus on demand forecasting, inventory optimization, warehouse utilization/recommendation, logistics/route optimization, and explainable recommendations.

**Important:** These are not official FCI, PDS, or Government of India records. Values, locations, distances, delivery outcomes, and labels are simulated. Replace or validate against official data before making real-world operational claims.

## Requirements
Python 3.10+ recommended:
```bash
pip install pandas numpy
```

## Run order
```bash
python 01_generate_core_data.py --output-dir data/core --seed 42
python 02_generate_logistics_data.py --input-dir data/core --output-dir data/logistics --seed 43
```
The fixed seeds make results reproducible. Change `--seed` to generate another synthetic sample.

## Script 1: core data
Creates:
- `products.csv` — product/SKU metadata, unit, priority and shelf life.
- `districts.csv` — synthetic demand nodes with population, rural share, road access and approximate coordinates.
- `warehouses.csv` — capacities, handling limits, costs, reliability and coordinates.
- `monthly_demand_history.csv` — monthly district-product demand history, suitable for time-series forecasting.
- `inventory_snapshot.csv` — stock, reservations, lead times, safety stock and expiry risk; useful for reorder and stockout analysis.
- `procurement_orders.csv` — supplier/order dates, expected vs actual delivery and costs; useful for lead-time and supplier analysis.

## Script 2: logistics and optimisation data
Uses the core files to create:
- `vehicle_fleet.csv` — simulated vehicle capacities, availability and operating costs.
- `historical_shipments.csv` — shipment quantity, selected warehouse/vehicle, simulated distance/time/cost and delivery outcome.
- `route_allocation_candidates.csv` — multiple warehouse/vehicle candidates per shipment with cost/time/stock/capacity features and a simulated recommendation label.
- `warehouse_utilization.csv` — stock-to-capacity summary for analytics dashboards.

## Suggested modelling tasks
1. **Demand forecasting:** group `monthly_demand_history.csv` by `district_id + product_id`, split chronologically into train/validation/test sets, forecast `demand_quintals`.
2. **Inventory optimization:** use forecast demand, `inventory_snapshot.csv`, lead time and safety stock to estimate reorder points and replenishment quantities. A basic reorder point is expected demand during lead time + safety stock.
3. **Warehouse recommendation:** rank feasible warehouses by distance, stock availability, remaining capacity, handling capacity, reliability and cost.
4. **Route/logistics optimization:** compare candidate routes by cost, estimated time, vehicle capacity, stock shortfall and availability. Treat `recommended_candidate_label_simulated` as a synthetic baseline label only; it is not ground truth.
5. **Explainability:** surface the features that most affected a recommendation (e.g., lower cost, shorter travel time, stock availability, capacity feasibility).

## Caveats for the teammate
- Route distances are haversine-based distances multiplied by a random road-detour factor; they are **not** real road-network distances. Use a road routing API or verified road-distance dataset for deployment-quality route optimization.
- Some candidate rows intentionally have stock shortfalls or vehicle capacity violations so models can learn feasibility constraints. Do not treat these as operationally feasible routes.
- `utilization_ratio_simulated` is based on the generated inventory snapshot and may be capped at 1.5 for display. Validate aggregation logic before production use.
- Synthetic recommendation labels are generated by a simple objective proxy, not an expert-validated policy. For a rigorous evaluation, define the optimization objective and constraints with the project team.
- The current data uses generic district names and approximate coordinates to avoid implying that records represent real facilities.
