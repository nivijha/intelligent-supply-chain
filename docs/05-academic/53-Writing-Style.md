# Writing Style

---

## 48. Writing Style

### Academic Language

- Professional but not overly complicated
- Clear headings and subheadings
- Tables for structured information
- Bullet points for lists
- Numbered requirements
- Short technical explanations

### Formatting

- Consistent heading hierarchy (H1, H2, H3)
- Code blocks for technical content
- Tables for comparisons
- Bold for emphasis on key terms
- Links for cross-references

### Content Rules

- No buzzwords unless actually implemented
- No claims of real-time processing unless implemented
- No claims of production-grade scalability
- No claims of autonomous decision-making
- No claims of government deployment
- No claims of superior performance without evidence

### Placeholders

Use these markers where implementation results are not yet available:

- [TO BE EVALUATED] - For metrics pending experiments
- [TO BE FILLED AFTER EXPERIMENT] - For specific numbers
- [PLACEHOLDER FOR RESULT] - For anticipated outputs

### Consistency

- Every section must align with the stated architecture
- No introduction of technologies not in the architecture
- Consistent terminology throughout
- Consistent notation for components and data flows

### Figures and Diagrams

- Architecture diagrams in ASCII or draw.io
- ER diagrams in standard notation
- Sequence diagrams for workflows
- Data flow diagrams for processes
- UML diagrams as specified
